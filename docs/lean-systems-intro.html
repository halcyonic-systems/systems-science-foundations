Klir, Bunge, and Mobus — a preliminary formalization

Starting with Klir

The simplest rigorous definition of a system is Klir's (2001, Eq. 1.1): a pair S = (T, R) — a set of things and a relation among them. No more, no less. Systems science has elaborated this kernel for 50+ years. The question this formalization poses: which elaborations are mathematically sound, and how do they relate?

Definition (Klir System). 
-- Klir (2001), Eq. 1.1 — the common-sense definition
structure KlirSystem (α : Type*) where
  things   : Set α          -- T: the set of things (thinghood)
  relation : Set (α × α)   -- R: the relation on things (systemhood)

Every formal systems theory in the Klir tradition is an elaboration of this pair.

What the pair contains

The definition looks trivially simple, but Klir (Ch. 2) emphasizes that T and R are "extremely rich in content":

  1. T can be a single set A, or a family of distinct sets {A1, A2, …, An}.
  2. When T is a family, R ⊆ A1 × A2 × … × An — yielding binary (R ⊆ A²), ternary (R ⊆ A³), or mixed (R ⊆ (A × A) × A) relations.
  3. An object is a system if and only if it can be described in a form conforming to Eq. 1.1 (Klir, p. 5).

The formalization commits to a specific reading:

  • T is a single set (Set α).
  • R is a binary relation (Set (α × α)).

This is the natural base case — it captures the structure common to all three frameworks. Richer relational forms (ternary, mixed) would require dependent types or indexed relation families. The current choice keeps the types simple enough that projection maps compose by rfl.

Bunge's Rigorous Elaboration

Bunge's (1979) insight: Klir's T should be split. Some things are components; others are environment — they interact with components but are outside the system. Separating them is not optional; it's what "system" means. But before Bunge can split T, he needs a primitive that Klir left implicit: what does "interact" mean?

The acts-on primitive

Bunge's foundation is causal:

  • a ▷ b (a acts on b): a modifies b's trajectory or behavior.
  • Bonded(a, b): at least one acts on the other — i.e., a ▷ b ∨ b ▷ a.
  • Bonding is symmetric; action is not (agent/patient asymmetry).
Definition (Action and Bonding). 
-- Bunge §1.2: a ▷ b means a modifies b's trajectory
class ActsOn (α : Type*) where
  actsOn : α → α → Prop

-- Two things are bonded if at least one acts on the other
def Bonded {α : Type*} [ActsOn α] (a b : α) : Prop :=
  a ▷ b ∨ b ▷ a

With ActsOn in hand, Bunge defines:

  1. Environment of σ: every thing not in its composition that is bonded with some component — ℰA(x) = {y ∈ Θ | y ∉ 𝒞A(x) ∧ ∃z(z ⊏ x ∧ (y ▷ z ∨ z ▷ y))}.
  2. Minimal model of σ at time t: the triple sA(σ, t) = ⟨𝒞A, ℰA, 𝒮A⟩ — composition, environment, structure (Bunge §1.2).
Definition (Concrete System). 
-- Bunge (1979) Def 1.1–1.2: the CES triple ⟨C, E, S⟩
structure ConcreteSystem (α : Type*) [ActsOn α] where
  composition : Set α          -- C: the components
  environment : Set α          -- E: external things bonded with C
  structure'  : Set (α × α)   -- S: the relations
  disjoint    : composition ∩ environment = ∅
  structure_on : ∀ p ∈ structure', p.1 ∈ composition ∪ environment ∧
                   p.2 ∈ composition ∪ environment
  bondage_nonempty : ∃ a ∈ composition, ∃ b ∈ composition, a ≠ b ∧ Bonded a b

Bunge states this across several pages. The formalization compresses it to three data fields and three constraints:

  • disjoint: C ∩ E = ∅ — components and environment share nothing.
  • structure_on: every pair in S involves elements of C ∪ E.
  • bondage_nonempty: at least two distinct components are bonded.

How Bunge extends Klir

The relationship is precise:

  1. Klir's undifferentiated T splits into two disjoint subsets: C (composition) and E (environment), with C ∩ E = ∅.
  2. Klir's R becomes S, constrained to pairs on C ∪ E.
  3. A third constraint is added: at least two distinct components must be bonded (bondage_nonempty).
  4. The projection back to Klir forgets E and recovers exactly (T, R):
Proposition (Bunge → Klir projection). 
-- Bunge → Klir: forget environment, recover (T, R)
def ConcreteSystem.toKlir {α : Type*} [ActsOn α]
    (s : ConcreteSystem α) : KlirSystem α where
  things   := s.composition   -- T = C (not C ∪ E)
  relation := s.structure'    -- R = S

The map discards E and recovers Klir's pair:

  • T = C (composition becomes things).
  • R = S (structure becomes relation).

Two CES triples with the same composition and structure but different environments project to the same Klir system. Environment is exactly what Bunge contributes beyond Klir.

The System Language

Mobus's contribution is not just another tuple — it is a language. In Chapter 4, he proposes that the language of systems should possess

"both the characteristics of a natural language for expressing systems and the characteristics of a formal language (both mathematics and computation) making it useful in constructing computer models for simulation." — Mobus (2022), Ch. 4

The system language should be

"speakable" as well as "viewable" as well as "computable." People should be able to talk to each other without over-abstraction causing the loss of details and meanings that support real understanding. — Mobus (2022), p. 70

Thornton (2025) names the persistent gap from the other direction: we need "a hybrid between algorithmic computation and natural language so that systemness can move freely between simulations and human understanding." What Thornton describes is precisely Mobus's system language — a language that is speakable, viewable, and computable. Lean 4 is not that language. It is the verification layer beneath it: it does not replace the system language but validates that its mathematical commitments are sound.

The 8-Tuple

The original framework (Mobus 2022) used a 7-tuple. In the book revision (Mobus 2025), the environment E is elevated from a hidden element inside G to a first-class member, giving the revised 8-tuple:

Si,l = ⟨C, N, E, G, B, T, H, Δt⟩i,l

C — Components
The set of components at this system level, with optional fuzzy membership. Each component is itself a system at a lower level of organization. Mobus §4.3.
N — Internal Network
Flow network among components: a directed graph where real substances (matter, energy, messages) move with causal influence. Mobus Eq. 4.4: N = ⟨C, L⟩.
E — Environment ⟨O, M⟩
Unified environment object. O = the set of discrete environmental source/sink objects. M = milieu variables — ambient conditions that influence the system without discrete flow (e.g., temperature, humidity, salinity, pH, pressure). Elevated from hidden-in-G to first-class in the book revision (Mobus 2025).
G — External Flows
Graph connecting environmental objects O to interface components in C. Simplified from bipartite in the book revision; flow arrows determine source/sink directionality. G = ⟨oi ∈ O, cj ∈ C⟩.
B — Boundary ⟨P, I⟩
P = boundary properties, I = interface components that transport flows across the boundary. Mobus Eq. 4.6.
T — Transformations
Domain-specific transformation functions: how the system processes inputs into outputs. Parametric in the formalization — the exact form depends on what the system does.
H — History / Memory
Accumulated structural knowledge; captures the trajectory of system states over time. Mobus: "knowledge of itself." Parametric in the formalization.
Δt — Time Scale
Temporal resolution relevant to this level of organization. Taken as the eighth element; lifecycle dynamics (ΔS) operate at this resolution.
Definition (Mobus System). 
-- Mobus (2022/2025), revised Eq. 4.1: the 8-tuple S = ⟨C, N, E, G, B, T, H, Δt⟩
structure MobusSystem (α : Type*) (κ : Type*) (μ : Type*)
    (π : Type*) (τ : Type*) (η : Type*) (δ : Type*) where

  -- C: the set of components at this level
  components : Set α

  -- N: internal flow network among components
  internalNetwork : FlowNetwork α κ

  -- E: environment ⟨O, M⟩ (objects + milieu)
  environment : MobusEnvironment α μ

  -- G: external flows connecting O to interface components
  externalFlows : FlowNetwork α κ

  -- B: boundary ⟨P, I⟩ (properties + interfaces)
  boundary : MobusBoundary α π

  -- T: transformation functions (domain-specific, parametric)
  transforms : τ

  -- H: history / stored knowledge (domain-specific, parametric)
  history : η

  -- Δt: time scale / temporal resolution (domain-specific, parametric)
  timeScale : δ

The seven type parameters split into two groups:

  • Structurally active (α, κ, μ, π): participate in coherence constraints that the compiler enforces.
  • Carried data (τ, η, δ): no structural role in the ontology — domain-specific payload.

The five coherence constraints are:

network_components
The vertex set of the internal network N is exactly C. This is the formal content of Mobus Eq. 4.4: N = ⟨C, L⟩.
disjoint
C ∩ E.objects = ∅. Components and environment objects share no elements — mirroring Bunge Def 1.2.
interfaces_sub
The boundary's interface components I ⊆ C. Interfaces are components, not external objects.
bipartite
Every external flow edge crosses between E.objects and I. This is the constraint from which boundary completeness derives — it is not axiomatized but proved as a theorem (MobusSystem.boundaryComplete).
externalFlows_nodes
All external flow endpoints lie in E.objects ∪ I.

The derived boundary completeness is notable: Mobus states that the boundary mediates all system-environment interaction. In the formalization, this is not assumed — it follows from the bipartite structure of G. The compiler proves it as a consequence, not a postulate.

Three Layers

Three distinct layers, each serving a different function:

  1. System language (Mobus) — the speakable and viewable layer. How practitioners reason about, communicate, and diagram systems.
  2. BERT (Bounded Entity Reasoning Toolkit) — the computational implementation. Renders the 8-tuple as interactive models that can be built, explored, and simulated.
  3. Lean 4 — the formal verification layer. Proves that the mathematical foundations beneath both are sound.

None replaces the others.

The Main Question

Given these three frameworks:

  1. Klir's pair S = (T, R) — thinghood and systemhood.
  2. Bunge's triple ⟨C, E, S⟩ — composition, environment, structure.
  3. Mobus's 8-tuple ⟨C, N, E, G, B, T, H, Δt⟩ — components through time scale.

Is there a principled map connecting them? Mobus's engineering elaboration is rich and computationally useful, but (as critics note) the mathematical descriptions lack the precision of Bunge and Klir. The question: is there a principled map from Mobus back to the Klir–Bunge foundation? If yes, Lean can prove it.

The Projections

Before the triangle can commute, we need three projection maps. Each discards structure that the target framework doesn't have vocabulary for:

  1. Mobus → Bunge: discard 6 categories of engineering detail.
  2. Bunge → Klir: discard environment.
  3. Mobus → Klir: discard everything at once.

The information loss at each step is formally characterized in the Lean codebase.

Mobus → Bunge: discard engineering detail

The 8-tuple maps to the CES triple by keeping three fields and discarding six:

  • Kept: C → composition (exact), E.objects → environment (milieu M lost), totalRelation → structure (capacity κ lost).
  • Discarded: milieu M, boundary properties π, transforms τ, history η, time scale δ, capacity κ.

The key operation is totalRelation: it unions the internal and external flow networks, then drops capacity labels via FlowNetwork.toRelation.

Definition (Bridge map). 
-- The total relation: internal + external, capacities discarded
def MobusSystem.totalRelation (sys : MobusSystem α κ μ π τ η δ) : Set (α × α) :=
  sys.internalNetwork.toRelation ∪ sys.externalFlows.toRelation

-- Mobus → Bunge projection (Bridge.lean)
def MobusSystem.toBunge (sys : MobusSystem α κ μ π τ η δ) : ConcreteSystem α where
  composition := sys.components            -- C: exact
  environment := sys.environment.objects   -- E: milieu M lost
  structure'  := sys.totalRelation         -- S: capacity κ lost

The field assignment is not the whole story. The definition must also prove that Bunge's three constraints hold for the Mobus data:

  1. disjoint: follows from Mobus's own disjoint axiom.
  2. structure_on: follows from totalRelation_on.
  3. bondage_nonempty: the substantive step — it extracts an edge from the internal network, uses network_components to place both endpoints in composition, no_self_loops for distinctness, and FlowInducesAction to establish the bond.

The bridge is well-defined because Mobus's coherence constraints imply Bunge's. The six projected-away categories are not deficiencies — they mark precisely where Mobus's engineering orientation led to distinctions that Bunge's philosophical orientation did not require.

Bunge → Klir: discard environment

-- Bunge → Klir: forget environment
def ConcreteSystem.toKlir (s : ConcreteSystem α) : KlirSystem α where
  things   := s.composition   -- T = C
  relation := s.structure'    -- R = S

Mobus → Klir: discard everything at once

-- Mobus → Klir: directly to (T, R)
def MobusSystem.toKlir (sys : MobusSystem α κ μ π τ η δ) : KlirSystem α where
  things   := sys.components       -- T = C
  relation := sys.totalRelation    -- R = N.toRelation ∪ G.toRelation

The question is now concrete: do these three maps compose correctly? Does going Mobus → Bunge → Klir produce the same (T, R) as going Mobus → Klir directly?

The Crown Jewel: Triangle Commutes

Theorem (Triangle Commutes). 
-- Mobus (2022) cites Klir (2001) as inspiration (Ch. 4, p. 14).
-- Bunge (1979) cites Klir and Valach (1967). Neither cites the other.
-- This theorem proves both paths — Mobus→Bunge→Klir and Mobus→Klir directly —
-- produce definitionally identical results.

theorem triangle_commutes {α κ μ π τ η δ : Type*} [ActsOn α]
    (sys : MobusSystem α κ μ π τ η δ)
    (hf : FlowInducesAction sys.internalNetwork)
    (hg : sys.internalNetwork.edges.Nonempty) :
    (sys.toBunge hf hg).toKlir = sys.toKlir := rfl
Proof.

We must show (sys.toBunge hf hg).toKlir = sys.toKlir.

Left-hand side:

  1. (sys.toBunge hf hg).toKlir
  2. = { things := (sys.toBunge ..).composition, relation := (sys.toBunge ..).structure' }  (expand toKlir)
  3. = { things := sys.components, relation := sys.totalRelation }  (expand toBunge)

Right-hand side:

  1. sys.toKlir
  2. = { things := sys.components, relation := sys.totalRelation }  (expand toKlir)

The two sides are identical terms. Lean's kernel confirms this by rfl — no proof search, no lemma invocation. The definitional equality traces to both Bunge and Mobus inheriting T = Set α and R = Set (α × α) from Klir without changing the mathematical type. ∎

This is what formal grounding looks like: two researchers who never cited each other, working from the same Klir root, arrived at structures that compose cleanly. The compatibility was discovered through formalization, not claimed by any author.

Convergence and Choice

The rfl is clean — perhaps too clean. It depends on a formalization choice. Consider two readings of Bunge's "structure":

  1. Flat reading: structure is Set (α × α) — a single relation. This is what ConcreteSystem uses.
  2. Family reading: structure is Set (Set (α × α)) — a "set of relations" (Bunge's plural). This is what RichConcreteSystem implements.

Under the family reading:

  • The Mobus → Rich Bunge projection creates a 2-element structure family: {N.toRelation, G.toRelation} — preserving the internal/external distinction.
  • The Rich → Klir projection must flatten this family via ⋃₀ (set union) to produce a single relation R.
  • The triangle still commutes, but the proof is no longer rfl:
Theorem (Rich Triangle Flatten). 
-- With structure as a family, flatten is an explicit step
-- ⋃₀ {A, B} = A ∪ B requires simp, not rfl
theorem toRichBunge_flatten_eq (sys : MobusSystem α κ μ π τ η δ) :
    (sys.toRichBunge hf hg).flatten = sys.totalRelation := by
  simp [RichConcreteSystem.flatten, MobusSystem.toRichBunge,
    MobusSystem.totalRelation, Set.sUnion_pair]

The gap between rfl and simp:

  • rfl — syntactic identity. The two expressions are the same computation; the type-checker confirms without reasoning.
  • simp — semantic equality. The expressions compute to equal values, but the checker needs a lemma (Set.sUnion_pair: ⋃₀ {A, B} = A ∪ B) to see it.

Both are true. But rfl works only because the flat representation hides an information-loss step that the family version makes explicit: to reach Klir's (T, R), you must forget not just environment but the organization of relations — which bonds are internal and which cross the boundary.

What matters is that both versions produce valid proofs:

  1. The compatibility does not depend on a particular reading of Bunge.
  2. It holds under the simple reading (rfl) and the more faithful reading (simp).
  3. When three independent researchers arrive at structures that compose cleanly under multiple formalizations, that is evidence the decomposition reflects something real about systemhood, not about formalization choices.

The analogy in mathematics: when the same structure appears independently in different branches — groups in algebra, symmetries in geometry, automorphisms in topology — that is evidence the structure is natural, existing independently of any one context. The commuting triangle, robust under different readings of its vertices, suggests that Klir's (T, R) kernel is similarly natural in systems science: the minimal structure that any coherent account of systemhood must contain.

What the Compiler Also Found

While formalizing Bunge Def 1.6, Lean rejected the definition as stated. Bunge writes the subsystem relation is:

  • Reflexive — requires a R a for all a.
  • Asymmetric — requires that if a R b then ¬(b R a).
  • Transitive.

Reflexivity and asymmetry are contradictory: reflexivity demands a R a; asymmetry forbids it. The correct property is antisymmetry (if a R b and b R a then a = b). The compiler caught what 47 years of reading did not.

Theorem (Subsystem Antisymmetry). 
-- Correcting Bunge Def 1.6: "asymmetric" should read "antisymmetric"
theorem subsystem_antisymm_components {α : Type*} [ActsOn α]
    {σ₁ σ₂ : ConcreteSystem α}
    (h₁₂ : Subsystem σ₁ σ₂) (h₂₁ : Subsystem σ₂ σ₁) :
    σ₁.composition = σ₂.composition ∧
    σ₁.environment = σ₂.environment ∧
    σ₁.structure' = σ₂.structure' :=
  ⟨Set.Subset.antisymm h₁₂.1 h₂₁.1,
   Set.Subset.antisymm h₂₁.2.1 h₁₂.2.1,
   Set.Subset.antisymm h₁₂.2.2 h₂₁.2.2⟩

Even rigorous authors make errors that survive publication. Proof assistants are for exactly this.

Emergence, Briefly

Theorem (Emergence Decomposition). 
-- Bunge Def 1.13(i): emergence as symmetric difference of property sets
-- (snapshot formalization; temporal refinement ongoing)
theorem novelty_eq_emergent_union_lost {P : Type*}
    (before after : PropertySnapshot P) :
    qualitativeNovelty before after =
      lostProperties before after ∪ emergentProperties before after := by
  simp [qualitativeNovelty, emergentProperties, lostProperties]

Philosophical debates about emergence can span hundreds of pages. The formal definition reduces to set operations:

  • emergentProperties = after ∖ before (properties that appear).
  • lostProperties = before ∖ after (properties that disappear).
  • qualitativeNovelty = lost ∪ emergent = symmetric difference.

simp closes it.

What this points toward: a machine-checkable grammar beneath the system language. Three layers, each serving a distinct function:

  1. Lean 4 validates the mathematical foundations.
  2. Onto-viz tracks how well implementations cover the reference frameworks — which concepts are present, partial, or missing.
  3. BERT renders the 8-tuple as interactive models that practitioners can build and explore.

Mobus's vision — a language that is speakable, viewable, and computable — now has formal verification, coverage tracking, and computational implementation. The more immediate value is the compiler's discipline: it forces precision on concepts that have been written loosely for decades.

But the deeper finding is structural. Three frameworks — developed across different decades, disciplines, and continents, with no mutual citation between Bunge and Mobus — decompose systemhood in compatible ways. The commuting triangle holds under both a simple and a faithful reading of the source material. This is not an artifact of clever formalization; it is evidence that the decomposition into things, relations, and environment is a natural structure of systems science itself — one that any coherent account of systemhood converges toward.

The standard view of proof assistants: you know what to prove, and the tool checks your proof. That is not what happened here. The rfl was discovered, not anticipated. The published error was found, not sought. The proof assistant was not a verification tool but an instrument of inquiry — it forced precision that revealed structure nobody had seen, including the original authors. Lean did not create this convergence. It made it visible.
