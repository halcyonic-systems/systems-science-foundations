The Commuting Triangle

How a proof assistant discovered that three independent systems ontologies were secretly the same mathematics — and what categories revealed about their differences

~4,010 lines of Lean 4 31 files Zero sorrys February 2026

01 The Puzzle

Three frameworks. Three eras. Two completely independent elaborations of the same root.

In 1969, George Klir published what may be the simplest useful definition of a system: a set of things and a relation on those things. S = (T, R). That's it. Ten years later, the philosopher Mario Bunge took Klir's seed and grew it into an ontological framework — adding the concept of environment to produce his CES triple ⟨C, E, S⟩, published in the fourth volume of his Treatise on Basic Philosophy. Forty-three years after Bunge, the systems engineer George Mobus independently returned to Klir and elaborated in a completely different direction: typed flows, boundaries, milieu, transforms, history, and time scale, producing an eight-component tuple for his Systems Science textbook.

Neither Bunge nor Mobus references the other. They developed their frameworks independently, from the same Klir root, for different audiences — one philosophical, one engineering. The natural question: are they mathematically compatible?

No one had asked. The author's position to do so was accidental: a student of Cliff Joslyn (himself a student of Klir), who built a software tool on Mobus's framework and then formalized Bunge's axioms in a proof assistant. The answer turned out to be more interesting than simple compatibility.

02 The Common Root

Klir's definition is almost shockingly minimal. A system is a set of things and a relation on those things:

S = (T, R) — where T is a set of things and R is a relation on T.

That's the entire definition. No boundary, no flows, no transforms, no time. Just elements and how they connect. In Lean 4 type theory, this becomes T = Set α and R = Set (α × α) — a set and a binary relation, the simplest possible mathematical substrate for "system."

What makes Klir's definition powerful is not what it says but what it enables. Both Bunge and Mobus start here and elaborate. Both inherit the same mathematical types for T and R. Both add structure on top of Klir without ever changing the underlying representation. This fact — that the elaborations preserve the root types — is invisible in the prose but structurally undeniable in the type system.

03 Two Parallel Paths

Bunge's Philosophical Path (1979)

Bunge takes Klir's (T, R) and asks: what is a system embedded in? He adds environment, producing the CES triple ⟨C, E, S⟩ — composition, environment, and structure.

  • Defines subsystem as a partial order
  • Introduces emergence as set operations
  • Builds hierarchical levels via recursive decomposition
  • Source: Treatise on Basic Philosophy Vol. 4, Ch. 1

Mobus's Engineering Path (2022)

Mobus takes Klir's (T, R) and asks: what does a system need to function? He adds flows, boundary, milieu, transforms, history, and time scale, producing an 8-tuple.

  • Typed flow networks with parametric capacity
  • Boundary as a bipartite interface
  • Transform functions and state history
  • Source: Systems Science Ch. 4 + 2024 revisions

886 lines to formalize · 6 modules

The divergence is substantial. Mobus's 8-tuple ⟨C, N, E, G, B, T, H, Δt⟩ contains six categories of information that have no counterpart in Bunge's triple: milieu, capacity, boundary properties, transforms, history, and time scale. These mark precisely where the engineering tradition elaborated concepts the philosophical tradition did not require.

But underneath both elaborations, Klir's (T, R) persists. The question is whether projecting both frameworks back to Klir produces the same result.

What the compiler found: Bunge's Definition 1.6 describes the subsystem relation as "reflexive, asymmetric, and transitive." A relation cannot be both reflexive and asymmetric (reflexivity gives a ≤ a; asymmetry says a ≤ b and b ≤ a implies a ≠ b, contradicting a = a). He means antisymmetric — a partial order. In print for 47 years. The proof assistant caught it immediately.

04 The Commuting Triangle

The central result. Both paths from Mobus's 8-tuple back to Klir's (T, R) produce definitionally identical results. Not "isomorphic." Not "equivalent up to some transformation." Identical. The proof is the Lean keyword rfl — reflexivity — meaning the compiler checked that the two expressions evaluate to the same term without any computation.

Figure 2 — The commuting triangle. The solid path Mobus → Bunge → Klir equals the dashed path Mobus → Klir by rfl.

The rfl proofs trace to both authors inheriting T = Set α and R = Set (α × α) from Klir without changing the mathematical type.

This was not claimed by any of the three authors. It was discovered through formalization. The compatibility of these independently developed frameworks is a structural fact about their shared mathematical foundation, made visible only when a proof assistant forced every definition into explicit type theory.

05 What the Compiler Found

The proof assistant told us things about these ontologies that decades of reading had not. Beyond the commuting triangle itself, the formalization process produced a series of findings — some confirming the source texts, others correcting them, and a few revealing entirely new structure.

The most striking pattern: deep theorems proved by trivially simple tactics. Selection composition (Bunge's Theorem 1.2) proves by rfl. Emergence decomposes into set operations via simp. These are not trivially expected — they confirm that the right mathematical representations make deep conceptual claims definitionally true.

Six categories of information loss between Mobus and Bunge: milieu (ambient non-discrete influence), capacity (quantitative edge data), boundary properties (P structure), transforms (state transition functions), history (accumulated state trajectory), and time scale (Δt). Two Mobus systems agreeing on (C, E.objects, totalRelation) project to identical CES triples — everything else is lost in the bridge.

06 Categorification: Making Relationships Visible

The commuting triangle tells us the three frameworks agree when projected to their common root. But what about the structure of the relationships themselves? Category theory gives us the vocabulary to ask: when we say "Mobus refines Bunge," what kind of refinement is it? What is preserved, and what is forgotten?

The Ordering Triangle

There are three natural ways to order systems by their subsystem relationships, depending on how much structure you track. The family ordering (tracking individual relations like N and G separately), the refinement ordering (requiring only that each relation has a coarsening), and the flat ordering (using only the union of all relations). Each defines a category. The forgetful functors between them are faithful (they don't create spurious relationships) but not full (they lose distinctions).

Figure 3 — The ordering triangle. Three categories on the same objects, connected by forgetful functors (⤇). Faithful but not full — explicit Fin 2 counterexamples prove each step is strict.

The non-fullness results are constructive: explicit witnesses on Fin 2 (systems with just two elements) show that a refinement-subsystem pair need not be a family-subsystem pair, and a flat-subsystem pair need not be a refinement-subsystem pair. The choice of structure representation determines which subsystem ordering you get — different readers of these frameworks are implicitly working in different categories.

Bridge Factorization

The Mobus-to-Bunge bridge factors through the structure family representation. Mobus's separation of internal network (N) and external flows (G) is the natural two-element structure family. The bridge was always performing a flattening — the categorical language makes this visible:

Figure 4 — Bridge factorization. The dashed arrow decomposes into two functors: embed into the structure family, then flatten. A theorem about the relationship between frameworks that neither author stated.

This factorization is a theorem about the relationship between frameworks that neither Bunge nor Mobus stated. The extended diagram commutes: the factorization composes with the bridge to Klir, extending the original commuting triangle through the intermediate structure family.

07 The Bitcoin Application

The categorical tools developed for systems ontology turned out to have an immediate application in a companion formalization: modeling the relationship between Bitcoin's UTXO ledger and Ethereum's account-based ledger as a functor between categories.

The Bounded Resource Automata (BRA) formalization models Bitcoin's UTXO set as a category where morphisms are lists of valid transactions (traces), and Ethereum's balance map as a thin category ordered by total value. The collapse functor maps UTXO states to their balance equivalents.

The non-faithfulness of the collapse functor is the first genuinely new result requiring categories. It is not statable without Category instances — it requires injectivity on hom-sets.

The key properties proved categorically:

Essentially surjective (EssSurj): Every balance map has a UTXO preimage. No Ethereum state is unreachable from the Bitcoin side.

Not faithful (collapse_not_faithful_cat): Two distinct UTXO operations — consuming and reproducing u3 versus consuming and reproducing u7 — are distinguishable in UTXO-land but invisible at the balance level. The functor maps both to the unique identity morphism in the thin Ethereum category.

Conservation commutes (conservation_functor_obj): Total value is preserved by collapse at the functor-object level. Zero-fee transaction traces preserve value exactly.

What's Next

Phase 3 explores three directions at the frontier of applied category theory:

Polynomial functors map 5–6 of Mobus's 8 tuple components to Spivak's framework for systems with mode-dependent interfaces. The boundary-interface-flow triangle maps cleanly; time scale and milieu have no counterpart — they are engineering concepts that no purely algebraic framework captures.

Operad algebras correct Bunge's claim that "the set of all systems has no algebraic structure — not even the rather modest one of a semigroup." He's right about semigroups: not every pair of systems can compose. He's wrong about algebraic structure: composition is possible when boundaries match, and the patterns of boundary-matching form an operad. Systems form an operad algebra. This has been verified computationally using AlgebraicPetri.jl.

Petri net correspondence shows that BRA transactions translate directly to bounded Petri nets with a weighted place invariant w(p) = p+1. Open Petri net composition provides the compositional structure the Lean formalization currently lacks — and may inform the deferred MonoidalCategory BtcState.

Methodology

This formalization was produced collaboratively between a domain expert and an LLM (Anthropic's Claude) using the Lean 4 proof assistant. The human provided editorial judgment, interpretation choices when source text was ambiguous, and caught cases where LLM output was type-correct but conceptually wrong. The LLM provided Lean syntax fluency, Mathlib API navigation, and tactic proof generation. The compiler had final authority — zero sorrys means every claim is machine-checked.

The hard problems were not proof search. No proof required more than a few tactic steps. They were representational: should ActsOn reference HasStateSpace? Should environment be a field or derived? Should we use Set or Finset? These decisions propagate through the entire codebase and require understanding the source material, not Lean expertise.
