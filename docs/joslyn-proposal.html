Three Definitions, One Tradition

Klir: S = (T, R)

The simplest rigorous definition. A set of things and a relation among them (Klir, Facets of Systems Science, 2001, Eq. 1.1).

structure KlirSystem (α : Type*) where
  things   : Set α          -- T: thinghood
  relation : Set (α × α)   -- R: systemhood

Bunge: ⟨C, E, S⟩

Bunge adds environment as a first-class component. A system exists within something (Bunge, Treatise on Basic Philosophy Vol. 4, 1979, Def. 1.1–1.2).

structure ConcreteSystem (α : Type*) [ActsOn α] where
  composition : Set α          -- C: components
  environment : Set α          -- E: external things
  structure'  : Set (α × α)   -- S: relations on C ∪ E
  disjoint    : composition ∩ environment = ∅
  structure_on : ∀ p ∈ structure', p.1 ∈ composition ∪ environment ∧
                   p.2 ∈ composition ∪ environment
  bondage_nonempty : ∃ a ∈ composition, ∃ b ∈ composition, a ≠ b ∧ Bonded a b

Mobus: The 8-Tuple

Mobus elaborates Klir toward engineering methodology: typed flows, boundaries, interfaces (Mobus, Systems Science, 2022, Ch. 4). He cites Klir (2001) explicitly as inspiration.

structure MobusSystem (α κ μ π τ η δ : Type*) where
  components      : Set α                    -- C
  internalNetwork : FlowNetwork α κ           -- N = ⟨C, L⟩
  environment     : MobusEnvironment α μ      -- E = ⟨O, M⟩
  externalFlows   : FlowNetwork α κ           -- G
  boundary        : MobusBoundary α π         -- B = ⟨P, I⟩
  transforms      : τ                         -- T
  history         : η                         -- H
  timeScale       : δ                         -- Δt
  -- + 5 coherence constraints enforced at the type level

Neither Bunge nor Mobus references the other. They developed independently from a shared Klir root, 43 years apart.

The Commuting Triangle

Both paths from Mobus's 8-tuple back to Klir's (T, R) — via Bunge or directly — produce the same result. Not merely equal. Definitionally identical.

Theorem (Commuting Triangle). 
theorem triangle_commutes
    (sys : MobusSystem α κ μ π τ η δ)
    (hflow : FlowInducesAction sys.internalNetwork)
    (hedge : sys.internalNetwork.edges.Nonempty) :
    (sys.toBunge hflow hedge).toKlir = sys.toKlir := rfl
rfl

The proof is rfl — reflexivity. The type-checker confirms the two paths produce not just equal but definitionally identical values. This traces to both Bunge and Mobus inheriting T = Set α and R = Set (α × α) from Klir without changing the mathematical type. This was not claimed by any author. It was discovered through formalization.

What the Compiler Found

A 47-year-old error in Bunge

Bunge's Definition 1.6 states the subsystem relation is "reflexive, asymmetric, and transitive." No relation can be both reflexive and asymmetric. The compiler rejected it. The correct property is antisymmetry — making subsystem a partial order, not a strict order. The error has persisted through every edition.

Your question about S — answered

You asked: "S is a set of sets of tuples, right?" Yes. But the formalization proves it doesn't matter for the theorems:

theorem flatten_internal_commutes
    (r : RichConcreteSystem α) :
    ⋃₀ r.internalFamily = internalProjection r.composition r.flatten

Take the family of relations {Ri}, extract the internal part of each, then union — same result as first flattening everything, then extracting internals. The flat encoding is a faithful quotient. The compiler certifies this.

Boundary completeness — derived, not axiomatized

The systems-theoretic property that "all interaction is mediated by the boundary" is not assumed. It follows structurally from the bipartite constraint on external flows.

The Thermostat — Your Example, Three Frameworks

You used the thermostat in the 1995 paper to derive the internal-state requirement (Proposition 29) and the semantic-relation argument. Here it is formalized under all three frameworks. 160 lines of Lean, zero sorrys.

inductive Entity where
  | thermometer | controller | furnace | room | outsideAir
  deriving DecidableEq

instance : ActsOn Entity where
  actsOn
    | room, thermometer => True       -- room temp modifies thermometer state
    | thermometer, controller => True  -- measurement signal
    | controller, furnace => True      -- on/off command
    | furnace, room => True            -- heat delivery
    | _, _ => False

A modeling decision: outsideAir does not act on anything discretely. Its thermal effect enters through the milieu M, not a point-source flow. The system does not model the outsideAir → room heat-transfer pathway. This is the systemic stance in action.

The full 8-tuple with five coherence constraints proved:

def thermostatMobus : MobusSystem Entity Unit Unit Unit Unit Unit Unit where
  components      := {thermometer, controller, furnace}
  internalNetwork := intNet    -- therm→ctrl, ctrl→furnace
  environment     := ⟨envObjs, ()⟩  -- ⟨{room, outsideAir}, M⟩
  externalFlows   := extNet    -- room→therm, furnace→room

  transforms      := ()        -- the control rule (parametric)
  history         := ()        -- recent readings (parametric)
  timeScale       := ()        -- polling interval (parametric)
  network_components := rfl    -- N.nodes = C by definition
  disjoint := ...              -- C ∩ O = ∅
  interfaces_sub := ...        -- I ⊆ C
  bipartite := ...             -- G crosses between O and I
  externalFlows_nodes := ...   -- G.nodes ⊆ O ∪ I

Parametric fields use Unit — they carry no structural content here. In a richer model: τ = the if/then control rule, η = recent temperature readings, δ = 30-second polling interval. These are exactly the six information categories that the Mobus→Bunge projection discards.

Extracted from the Mobus 8-tuple by projection — not defined independently:

def thermostatBunge : ConcreteSystem Entity :=
  thermostatMobus.toBunge
    thermostat_flow_induces_action
    thermostat_internal_nonempty

After projection:

  • composition = {thermometer, controller, furnace} — exact from Mobus
  • environment = {room, outsideAir} — milieu M discarded
  • structure = all 4 causal pairs — capacity labels discarded

Two Mobus thermostats differing only in transforms (bang-bang vs. PID) project to the same Bunge CES triple. They differ only in what the controller does.

One more projection step strips the environment:

def thermostatKlir : KlirSystem Entity :=
  thermostatMobus.toKlir
  • things = {thermometer, controller, furnace} — components only
  • relation = all 4 causal pairs — including cross-boundary

A structural observation: room appears in the relation but not in the thing-set. The pairs (room, thermometer) and (furnace, room) are in R, but room ∉ T. The Klir projection drops the environmental distinction — room becomes a "phantom" entity, present in the relational structure but not counted among the system's things.

Theorem (Thermostat Triangle). 
theorem thermostat_triangle_commutes :
    thermostatBunge.toKlir = thermostatKlir := rfl
rfl

Both paths from the Mobus thermostat to Klir produce definitionally identical systems. The generic theorem, instantiated on a concrete system.

But all three descriptions miss the same thing. The controller's logic — if temperature < setpoint then turn on furnace — is a rule, not a law. It was selected from a variety of possible control functions. The meaning of "too hot" → "turn off furnace" is not captured by any structural description.

This is precisely your point from the 1995 paper: the feedback function f : Oi → Oe must be a rule (contingent entailment), not a natural law. The formalization reaches its limit here.

The Open Frontier

What the formalization cannot yet express

  • Variety — no concept of |X|, |S|, or C = X − S as a measure of constraint. Your Definitions 13, 17, 18 provide this.
  • Rule vs. law — ActsOn is opaque. It does not distinguish natural law (the ball rolls downhill) from rule (the controller turns on the furnace). Your distinction (1995, §4.2) is precisely what it collapses.
  • Control2 — active maintenance of equilibrium against disturbance requires temporal reasoning and second-order constraint the snapshot model does not support.
  • Metasystem transition — emergence of a new control level requires your hierarchical variety theory to even state formally.

What your framework provides

Variety gives the 8-tuple a measure. Mobus's component set C has dimensional variety n = |C|. His capacity κ is a cardinal variety measure on edges. Your two-axis framework provides the quantitative layer his structural definition needs.

The semantic layer gives transforms internal structure. The transforms τ are the natural home for your contingent entailments — but τ is currently parametric, carrying no internal theory. Your framework distinguishes τ as law, τ as rule, and τ as code.

The hypergraph connection. Your 2018 work — Seeking a Categorical Systems Theory via the Category of Hypergraphs — connects to a formalization finding: Mobus's two-network decomposition (N, G) is a natural two-element structure family. We proved three distinct subsystem orderings exist on structure families, with forgetful functors that are faithful but not full.
